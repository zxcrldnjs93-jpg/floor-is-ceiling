# 랜딩톤 제출 QA

대회의 기본 평가 20점은 세부 기준이 공개되지 않았다. 이 체크리스트는 제출물의 완성도를 확인하기 위한 팀 기준이다. 각 결과에 빌드 식별자, 브라우저·OS, 화면 크기, 재현 절차와 증거를 남긴다.

## 실행

프로젝트 루트에서 Python 3.9 이상, Node.js 18 이상, Chrome 또는 Chromium으로 실행한다. `BUILD_DIR`에는 실제 배포할 `index.html`과 리소스를 넣는다. 인수를 생략하면 `site/dist/`를 검사하고, 그곳에 빌드가 없으면 `site/`를 검사한다.

```sh
qa/run.sh --static-only site/dist/
CHROME_BIN=/usr/bin/google-chrome qa/run.sh site/dist/
qa/run.sh site/dist/ --contrast qa/pairs.json --page-url https://example.test/landing/
```

`--page-url`은 배포할 공개 주소가 정해졌을 때 지정한다. 서브경로에 올릴 때는 끝을 `/` 또는 `/index.html`로 지정한다. 정적 검사는 이 주소, HTML의 절대 canonical, `https://qa.invalid/` 순으로 내부 링크를 판정한다. Chrome은 `--page-url`을 생략하면 `https://qa.invalid/`를 사용한다. Chrome의 탭 요청은 DevTools 파이프로 받고 배포 폴더 파일을 응답한다. 지정한 주소나 외부 리소스에 접속하지 않는다. 외부 리소스 요청, 배포 폴더에 없는 리소스, JavaScript 예외, 브라우저 오류 로그 등은 실패로 기록한다.

`--contrast`에 현재 디자인의 실제 조합을 담은 JSON을 넘긴다. 아래 값은 형식 예시다. 라이트·다크, 기본·호버·포커스 상태의 실제 전경색과 배경색을 기록한다.

```json
[
  {"label":"라이트 본문", "fg":"#181818", "bg":"#FFFFFF", "type":"text"},
  {"label":"다크 큰 제목", "fg":"#FFF", "bg":"#191919", "type":"large"},
  {"label":"입력 경계와 인접 배경", "fg":"#666", "bg":"#FFF", "type":"ui"}
]
```

| 종료 코드 | 의미 |
|---|---|
| `0` | 실행한 자동 검사 통과. `검토` 항목은 별도로 확인한다. |
| `1` | 한 개 이상의 자동 검사 실패. 터미널 또는 `report.json`에 근거가 나온다. |
| `2` | 입력 문제. 배포 폴더, `index.html`, 옵션 또는 대비 JSON을 확인한다. |
| `3` | Chrome 검증 환경 문제. 정적 검사 결과는 터미널에 먼저 남는다. |

정상적인 여러 화면 길이의 페이지는 `정적 검사 PASS`, `Chrome 검사 PASS · 8개 조건 · 실패 0개`를 출력하고 `qa/out/run-*/`에 조건별 상단·중간·하단 PNG 최대 24장과 `report.json`을 남긴다. 한 화면에 모두 들어가면 해당 조건의 상단만 저장한다. 스크린샷은 자동 스크롤이 도달한 지점이므로, 실제 위치는 보고서의 `scrollY`로 확인한다.

Chrome이 `SingletonSocket` 경로 길이 오류를 반환하면 `QA_OUT=/tmp/ltqa qa/run.sh site/dist/`처럼 짧은 결과 경로를 지정한다. C11 전용 경로와 기대 출력은 [C11-RUN.md](C11-RUN.md)에 있다.

현재 샌드박스에서는 Chrome의 `setsockopt`, Chromium Headless Shell의 `shutdown`이 각각 `Operation not permitted`로 거부됐다. 조율 담당자는 Chrome 표준 샌드박스가 동작하는 로컬 터미널에서 위 `CHROME_BIN` 명령을 실행한다. 설치된 실행 파일 경로와 실제 배포 폴더에 맞춰 값을 바꾼다. 첫 번째 명령은 브라우저 없이 실행할 수 있다.

## 성능과 안정성

| 지표 | 팀 초기 목표 | 확인 |
|---|---|---|
| LCP | 2.5초 이내 | `report.json`에서 `lcpMs`. 공개 후 실제 방문 데이터의 75백분위도 확인한다. |
| CLS | 0.10 이하 | `cls`의 초기 세션 점수. 수동으로 글꼴 교체, 이미지 로딩, 펼침과 고정 장면 해제를 본다. |
| 배포 용량 | 원본 합계 1.5 MiB 이하 | 숨김 항목을 제외한 배포 파일의 디스크 크기 합계. 압축 전송량은 배포 후 별도로 기록한다. |
| JS 용량 | JS 합계 200 KiB 이하 | `.js`, `.mjs`, `.cjs` 파일과 `index.html`의 인라인 JS를 합산한다. |
| 초기 JS 실행 | 기본 250 ms, CPU 4배 감속 500 ms 이하 | `scriptMs`는 Chrome `ScriptDuration`을 ms로 변환한 값이다. 초기 화면의 대기 구간에서 얻으며 QA 계측 비용도 일부 포함된다. |

- [ ] `lcpMs`, `cls`, `scriptMs`의 `검토` 항목을 확인한다. 초기 지표는 각 조건에서 새 탭으로 시작해 캐시를 끄고 탐색 후 최소 3초에 채집한다. 실제 접속의 DNS·CDN·압축·망 지연과 스크롤 이후 지표는 별도로 잰다.
- [ ] 콘솔 오류, 미처리 Promise, 로컬 리소스 404, 모듈·글꼴 로딩 실패를 0건으로 확인한다. 첫 화면, 아래로 스크롤, 핵심 체험, 초기화, 마지막 CTA를 실행하고 다시 확인한다.
- [ ] DevTools CPU 감속 4배와 실기기 저사양 조건에서 핵심 인터랙션을 연속 실행한다. Performance 기록에서 50 ms 이상 장기 작업과 입력 반응 지연을 확인한다. 탭 복귀와 화면 회전 뒤에도 같은 체험을 완료할 수 있는지 확인한다.

## 반응형과 크로스브라우저

- [ ] Chrome 자동 캡처 320×568, 390×844, 768×1024, 844×390 가로, 1440×900, 1920×1080을 비교한다. 390×844의 CPU 4배 감속과 움직임 줄이기 캡처도 확인한다. 브라우저가 가로 넘침을 감지해도 원인 요소는 스크린샷과 DevTools에서 찾는다.
- [ ] 320px부터 1920px까지 연속으로 조절한다. 문장 잘림, 세로 모드 전용 줄바꿈, 배경과 텍스트의 겹침, 화면 밖 CTA, 과도한 여백, 장면 전환 경계를 본다. 844×390 외에도 작은 568×320 가로모드를 확인한다.
- [ ] 데스크톱 Chromium·Firefox·Safari, Android Chrome·iOS Safari 실기기에서 첫 화면부터 마지막 CTA까지 진행한다. 모바일 주소창 접힘·펼침, 안전 영역, 회전 이후의 고정 장면, 스크롤 복귀를 본다. 운영체제·브라우저 버전을 기록한다.
- [ ] 실기기에서 탭, 길게 누르기, 드래그·놓기, 스크롤 중 손가락 이탈과 화면 회전을 시험한다. 드래그 영역 주변에서 정상 스크롤이 가능하고, hover 없이 핵심 내용을 발견할 수 있어야 한다. 기울기 입력이 있다면 권한 거부 뒤의 대체 동작도 확인한다.

## 접근성

- [ ] WCAG 2.2 AA 대비를 확인한다. 일반 텍스트 4.5:1, 큰 텍스트 3:1, UI 식별과 상태 전달에 필요한 비텍스트 요소와 그래픽 3:1을 적용한다. 큰 텍스트는 18pt 이상 또는 굵은 14pt 이상이다. 자동 계산은 지정한 불투명 sRGB 색 쌍에 적용한다. 사진·그라데이션·반투명 배경 위 콘텐츠는 실제 합성색과 가장 불리한 위치를 확인한다.
- [ ] Tab·Shift+Tab으로 화면 순서대로 이동한다. 링크와 버튼을 키보드로 동작시키고, 키보드 트랩이 없는지 확인한다. 포커스 표시가 보이며 스티키 요소에 완전히 가려지지 않아야 한다. 모달을 쓰면 닫은 뒤 포커스가 호출한 요소로 돌아오는지 확인한다.
- [ ] 콘텐츠 이미지의 `alt`가 전달해야 할 의미를 담고 장식 이미지에는 `alt=""`가 있는지 확인한다. SVG·캔버스·물리 장면은 접근 가능한 이름과 동등한 설명이나 조작 수단을 제공한다. 제목·영역 구조·컨트롤의 이름과 상태를 VoiceOver 또는 NVDA로 점검한다.
- [ ] 움직임 줄이기 설정에서 큰 장면 이동과 물리 반복 효과를 줄이면서 핵심 의미·체험·CTA에 도달할 수 있는지 확인한다. 자동으로 시작해 5초 넘게 이어지는 움직임은 필요한 예외를 제외하고 일시정지·중지·숨기기 수단을 확인한다. 번쩍임은 WCAG의 초당 3회 또는 임계값 기준을 적용한다.
- [ ] 필수 드래그에 단일 포인터 대체 동작을 제공한다. 예외·간격 조건을 고려해 터치 타깃의 24×24 CSS px 기준을 확인한다. 200% 텍스트 확대와 320 CSS px 폭에서 텍스트와 주요 조작부를 놓치지 않는지 본다.

## 한 장 규칙과 SEO·공유

- [ ] 내부 링크와 폼은 현재 문서에 머문다. 정적 검사는 HTML의 링크·폼 목적지·메타 새로고침과 앵커를 확인한다. 첫 로딩과 자동 스크롤 중 실행되는 History API 이동은 Chrome 검사에서 감지한다. 수동으로 메뉴, 체험 종료, 공유 버튼·모달·CTA를 눌러 클릭할 때만 실행되는 라우팅과 리다이렉트를 확인한다.
- [ ] 페이지 제목, 설명, 언어, 화면 너비에 맞춘 viewport, canonical을 확인한다. 검색 결과에 보여야 하는 페이지라면 공개 빌드의 robots 설정도 확인한다.
- [ ] `og:title`, `og:description`, `og:image`, `og:url`이 실제 제출 내용을 가리키는지 확인한다. OG 이미지는 공개 절대 주소의 1200×630 이미지로 준비하고, 이미지 대체 설명과 작은 미리보기의 잘림을 확인한다. 배포 이후 공유 미리보기의 제목·이미지와 최종 URL을 점검한다.
- [ ] 최종 증거에 브라우저별 체험 완료 여부, 실패 화면, 경고 처리 결과와 미검증 조건을 기록한다.
